# 状态与异步任务

## 先设计状态，再画成功界面

每个网络任务至少有 idle、validating、pending、success、error。支持取消的任务还需要 cancelled。加载开始要防重复请求，结束要恢复可操作状态，失败要保留用户输入。

```text
idle → validating → pending → success
           ↓            ↓
         error ←────── error
```

## 状态显示

| 状态 | 显示 | 操作 |
|---|---|---|
| 未开始 | 简洁说明与主要按钮 | 可编辑和提交 |
| 校验 | 必要时短时检查提示 | 阻止无效提交 |
| 下载/连接中 | spinner、任务说明、aria-busy | 禁止重复提交；必要时可取消 |
| 成功 | 已确认的结果数量和状态 | 清理输入或进入结果页面 |
| 失败 | 原因、影响、重试路径 | 保留输入；可编辑和重试 |
| 未知 | “未知”“未测速”“—” | 不用随机结果替代 |

## 乐观与确认式操作

修改视觉筛选可以立即生效。启动内核、启用系统代理、付费、删除和下载订阅等操作应以真正完成的结果为准。不能在 Promise 未完成时先显示“服务已连接”。

## 竞态与生命周期

对启停操作串行化；关闭请求必须能等待正在发生的启动完成并随后停止。快速重复操作只让最后的有效意图生效。组件卸载后不要把陈旧请求结果覆盖新页面数据。任何异常退出应更新状态并尝试清理资源。

## 错误类型

区分输入无效、HTTP 失败、内容为空、内容是 HTML、格式不支持、超时、端口冲突和权限失败。面向用户说明可执行的下一步；完整网络异常可能携带 URL/token，不应直接显示或写日志。

## 空状态

首次使用引导添加数据；无搜索结果提供清除筛选；删除后空列表不重新生成演示记录；请求失败不被解释为“没有记录”。未知数量不显示 0，除非已确认确实为空。
