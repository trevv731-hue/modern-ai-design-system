# v2 到 v3 迁移

## 保留什么

原来的 tokens、原生示例和历史设计偏好仍保留。旧版 A/B 对比页与重复的长篇设计规范已移入项目同级的整理备份，不再作为日常入口。v3 在 Web 工程中采用独立语义角色、可访问状态和详细验收。既有历史偏好矩阵是源项目文档，不代表用户在当前会话中新授予了额外权限。

## 新入口

`index.html` 为 v3 离线组件目录；`docs/README.md` 为详细手册。原 `.cursor/skills/hybrid-native-ui/code/demo.html` 作为 v2 参考保留。新业务页面采用 `dist/web/theme.css` 与 `components.css`。

## 推荐迁移次序

1. 先引入语义主题，确认正文和操作颜色。
2. 替换按钮、输入框、开关和徽标。
3. 分离导航材质和内容实底。
4. 接入真实异步状态，移除随机数据与虚假成功。
5. 检查键盘、缩放和减少动效。
6. 最后再统一复杂表格、弹窗和平台特有行为。

## API 与风险

v3 React 封装为新增源码 API，没有已发布包的兼容承诺。表单 value/onChange 保持业务控制。颜色角色 on-action/action 一起使用，不能只替换按钮背景。Dialog 使用原生模态行为，旧版显示隐藏逻辑不要同时控制。

## AetherLink

通过 `npm run sync:ui` 从指定目录同步固定产物到 `src/design-system/`，应用运行时不会依赖 D 盘路径。同步后重新构建并跑桌面测试；同步不包含用户节点或订阅凭据。
