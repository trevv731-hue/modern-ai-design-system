# 布局与响应式

## 桌面骨架

标题栏 52px；侧栏默认 212px；内容最大 1280px；页内边距默认 32px。主操作放在页面标题或任务卡片附近，系统开关放在稳定的辅助区域。列表、表单与统计数据之间使用明确的分组标题。

## 建议断点

| 宽度 | 结构 |
|---|---|
| ≥1280px | 完整侧栏；数据或组件目录可两列；页面外侧保留留白 |
| 960–1279px | 完整侧栏；辅助信息减少；卡片两列或单列 |
| 720–959px | 收紧页边距；长表单单列；优先保留核心操作 |
| <720px | 网站侧栏折叠为可访问菜单；表单单列；表格局部水平滚动 |

断点是布局变化点而不是设备名称。AetherLink 当前是桌面窗口，有原生最小宽度；组件目录支持窄屏，两者不能混为同一产品能力。

## 网格

主要任务卡片可使用 `minmax(0,1fr)`，避免长地址撑开网格。超过容器的服务器地址允许换行或显示可复制详情；不要在所有区域一律截断。指标区 3–4 列只适用于足够宽的容器。

## 滚动和固定区

整个窗口仅一个主要内容滚动区。侧栏和标题栏保持稳定；表格与代码允许必要的局部滚动。sticky 元素不应覆盖焦点；设置 scroll-padding-top 给锚点留空间。

## 弹窗

宽度使用 `min(480px, calc(100vw - 32px))`；高度不超过视口减去 48px；正文可滚动。小屏不把确认按钮放到视口之外。表单太长时应采用页面。

## 内容长度测试

用 80 字标题、很长服务器名、1000 字错误解释、空数据和 200% 字体验证。布局不以当前中文短文本为唯一依据。数字与单位尽量同组，不把单位甩到下一行。

## 托管平台个人主页（2026-10-19）

适用条件：GitHub Profile README 等不能自定义整页 CSS 的内容区域。优先用原生 Markdown 提供可选取文字、项目链接和折叠次要内容；装饰横幅使用仓库内 SVG；跟随主题时通过 picture/source 提供深浅配色与 img 备用源，明确要求固定浅色的作品则直接使用浅色 img，不能以系统偏好覆盖已确认的视觉选择。不要把整份作品集画进图片，也不依赖外部统计卡片承担核心信息。只展示已公开项目，避免将私有工程名称和入口带入公开介绍。

验证记录：在 GitHub 实际主页确认 README、项目链接与横幅加载；390px 视口无页面横向溢出，系统深色偏好可选中深色 SVG。横幅小字在手机端仅为辅助装饰，核心介绍仍保留正文。未验证边界：所有客户端主题覆盖行为、屏幕阅读器与长期缓存更新。后续按用户反馈移除深色横幅，直接复用 tokens/web.json 的 light 角色色（canvas、surface、ink、muted、line、accent），使用浅灰白背景与蓝色点缀；深色系统偏好下亦确认加载浅色横幅。GitHub 站点外壳配色由访问者自己的设置控制，README 不能覆盖。终端意象、固定浅色和中英混排是此个人主页选择，不推广为通用产品风格。


组件视觉迁移补充：本次将 web/components.css 的 Bento 实底卡片、badge 胶囊和 terminal 信息分层转为三份静态 SVG，配色与圆角由源 Token 读取，并提交最小快照及生成脚本，保证目标仓库独立重建。示意时间数据明确标注，项目正文和链接保持原生文字；没有将 SVG 示例按钮当作可操作控件。实际 GitHub 桌面与 390px 视口确认三图加载、项目预览链接指向对应公开仓库且无页面溢出。图片同路径更新可能仍命中缓存，关键改版使用新资源文件名并再次验收。未验证手机端装饰小字逐字可读、所有字体替换与完整辅助技术体验；视觉迁移不等同于 React 组件运行或交互复用。
