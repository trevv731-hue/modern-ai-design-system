# 版本、维护与贡献

## 内容归属

设计源为 tokens/web.json、web/components.css、web/react.tsx、web/catalog.cjs 和手写 docs。自动产物为 dist/web、index.html、token-reference.md 与 docs/components。不要仅编辑产物，随后构建会覆盖。

## 版本约定

增加向后兼容的组件和角色升级次版本；修复样式、说明和验证升级补丁版本；移除变量或改变交互语义升级主版本。新增组件必须包括真实预览、键盘行为、状态和验收条件。

## 评审流程

先写清楚要解决的真实任务，再提交状态矩阵和组件代码。评审比较默认、错误、加载和禁用状态，而不只看漂亮截图。未实现业务行为不能通过 toast 文案伪装为成功。

## 产物维护

构建应确定性输出；不用当前时间改变每个文件的内容。锁文件与 package.json 版本一致。增加资产记录来源和许可；不要上传 node_modules 或为了体积复制无用资源。

## 文档更新

用户长期约定：每次项目或实质迭代结束后，主动评估可回流经验，补充相关模式、组件或验证记录。优先更新现有专题，不重复积累；没有新增经验时说明即可。记录适用条件、实际验证与待验证范围，避免把单产品偏好写成全局规则。经验同步修改源文件，随后按变更范围构建和验证，不修改备份，不包含私人数据。

组件 JSON 是逐组件规范的真值。手写专题是横向工程约定。源引用记录访问日期，并区分官方要求和本系统主动选择的数值。新官方规范不自动覆盖产品已确定的交互，需评审实际影响。

## 多工具整合与能力声明（2026-10-17）

适用条件：交付本地工具箱、诊断工作台或第三方工具集成。问题是工具目录、文件存在和可执行功能容易混为一谈，历史会话提及某个工具也可能被误报为已经使用成功。

决策：分别记录上游仓库核对、历史提及、本地文件定位、依赖就绪与实际执行结果。工具目录提供选路，核心链路提供可复现命令；下载源码不标记为已安装，诊断发现文件时不标记为运行验证通过。上游源码保留许可、commit 与 SHA-256；专项脚本若含样本特征或固定路径，明确归为参考，不伪装为通用工具。采集数据、CA 私钥和依赖环境与可分享源码分开。

验证记录：本轮工具箱完成 51 个公开仓库元数据核对，固定 5 份上游源码快照；代理抓包、单次发包和重放使用本地 HTTP 与真实 TLS 服务验证，客户端信任代理 CA，代理单独信任测试源站 CA，未关闭 TLS 校验。8 项测试覆盖请求重放、凭据过滤、Webhook 输入及包文件名冲突。未验证边界：所有第三方引擎全量运行、真实移动设备、证书固定客户端与 WebSocket 帧重放。通用原则是如实区分各阶段证据；具体工具选型与端口属于单个项目选择。

## 多 AI 维护独立站点（2026-10-17）

适用条件：多个产品独立部署，但共享安全契约或设计规范。问题是重复脚本逐渐分叉、历史交接与当前规则冲突，以及跨站测试写死开发者目录后验证了旧副本。

决策：各仓库以 AGENTS.md 为当前规则入口，README 描述实际命令，历史交接注明时间与适用范围；项目内提取运行脚本的公共路径、构建开关和失败处理。跨项目测试通过显式环境变量指定源码目录，不将相邻项目或个人机器路径变成运行依赖。共享安全副本先检查一致性，不能自动覆盖有差异的一侧；主机、Cookie 等产品策略保留独立实现。减少重复不等于合并安全边界。

大文件重构按实际职责拆分，内部直接引用职责模块，原入口仅保留兼容导出；先核对声明和公开接口，再对照完整测试的失败基线，不能只凭核心测试通过声称功能完整。模块顺序统一为依赖、常量／辅助函数、组件、对外操作；格式配置随源码保存。移动文件还要检查动态导入和资源路径。确认无运行时引用的历史副本可以删除，不应为了“一致性检查”继续保留已经无职责的重复实现。

验证记录：两个独立站点的服务端 52 项与 19 项（含 5 项跨站集成）、核心前端 299 项通过，训练网站构建通过；移除无引用的加密副本后，3 份共用安全文件一致性检查通过。弹层拆分保留 138 个声明和 59 个公开导出，12 个职责模块之间无循环依赖。完整前端回归的拆分前后对照均为 4,854 项通过、9 项失败，失败文件集合一致；既有失败未修复，不应报告为全绿。未验证边界：真机交互、线上部署和打包体积优化。独立部署与显式契约检查可推广，具体站点的登录及公开访问策略属于产品约定。
