# 图标、插画和资源管理

## 图标

业务应用优先沿用现有 Lucide 图标系统：同一区域采用统一尺寸和笔画。常规图标 18–20px；辅助图标 14–16px。装饰图标 aria-hidden，独立图标按钮必须有名称。

不要混用多种线条风格；无需为每个空状态生成巨大的插画。应用标识可以使用本地 SVG，保留 viewBox，避免硬编码主题颜色。图标中的颜色尽量使用 currentColor。

## 品牌图标：先过剪影关

应用图标最终会被缩到 16–48px 显示，此时只剩**外轮廓**在传递信息，内部细节全部丢失。所以画图标的顺序应该是：先把剪影画到能一眼认出，再往里加细节。

判定的土办法：**把图缩到 48px，或者眯眼看**。如果认不出来，细节再多也没用。

一次真实踩坑（ActiveT 健身应用）：

| 尝试 | 结果 | 原因 |
|---|---|---|
| 壶铃（把手 + 圆壶身） | ❌ 读成**挂锁** | 把手悬在圆顶上方，正是挂锁的轮廓；极简剪影下无法区分 |
| 壶铃（加"颈"连接把手与壶身） | ❌ 仍像挂锁 | 轮廓比例没变，加细节救不了剪影 |
| 杠铃片（**外环镂空** + 孔） | ❌ 读成**垫圈 / 齿轮** | 镂空环在缩小后读作机械零件 |
| 杠铃片（**实心圆盘** + 中心孔） | ✅ 一眼认出 | 实心块 + 中心孔是最强的辨识特征 |

三条可复用的结论：

1. **实心块比镂空环辨识度高。** 缩小后镂空会被填成灰边，形状退化成"圈"，和垫圈、齿轮、光盘混在一起。
2. **避开有多义性的经典轮廓。** 圆 + 上方提手 = 挂锁；圆 + 右侧凸起 = 钥匙；圆角方 + 中间横条 = 电池。改细节不如换主体。
3. **中心孔比外缘缺口更耐缩。** 孔洞位于重心，缩小时不会糊掉；外缘的小缺口最先消失。

落地时 SVG 与 PNG 必须**几何一致**（同一份路径参数），否则 favicon 与主屏图标看起来是两种东西。PNG 各尺寸由脚本从同一组几何生成，不要手工导出——见 `训练手记/frontend/scripts/make-icons.mjs` 的做法：不依赖图形库，直接按几何判定逐像素填色，尺寸可任意切换。

## 图片

图片需注明来源、用途、许可、原始尺寸和导出规格。没有实际使用需求时不下载大量壁纸和字体来凑体积。组件截图应来自可运行目录，标明主题、密度和日期。

## 字体

Web 产物内置 Noto Sans SC 可变字体，通过本地 @font-face 加载，中文与拉丁文字统一排版。字体源和 SIL OFL 许可在 web/fonts/，构建复制到 dist/web/fonts/；fallback 包含 Microsoft YaHei UI，不依赖公网字体请求。AetherLink 安装包同时包含 OFL 许可。

## 输出结构

桌面应用品牌图标保留 SVG 原件，导出 512px PNG 和包含 16／32／48／64／128／256px 的 ICO；检查任务栏、窗口标题和高缩放下的可读性。示例实现已用于 SSH Desk。业务图标继续沿用统一笔画，不把每个动作换成品牌标识。

字体源文件和许可放在 `web/fonts/`，构建 CSS/JSON 放在 `dist/`。历史截图、旧版长篇规范和 A/B 对比页收在 `archive/legacy-2026-10/`；运行 `npm run package` 时才创建 `artifacts/` 输出目录。不把 node_modules 体积当作设计系统的内容价值。原始资源与演示资源分离。

## 按实物尺寸打印图片（2026-10-18）

适用条件：证件、标签等需要按毫米输出的图片排版。问题是原始照片的背景和透视使照片外框不等于实物边界，文档插图也可能按原比例适配指定的宽高框；仅设置宽高不足以证明最终打印尺寸。

决策：区分实物轮廓、图片画布和页面尺寸；以毫米定义目标，按 `pt = mm × 72 / 25.4` 换算。需要保持几何准确时先明确裁边与透视校正方案，保留原件，不用生成式重绘证件文字。最终导出 PDF，核对页数、每张图片的实际包围框并目视检查；打印说明写明纸型和“实际大小 / 100%”。此为通用交付原则，上下排两张属于本次文档选择。

验证：本次在线文档导出为一页，两张图片均完整显示；PDF 图片包围框相对目标有约 0.1 毫米的取整差异。未验证实体打印机、驱动缩放及照片透视校正，不能把文档外框尺寸声明为实物轮廓完全等大。经验记录不保存原始证件、身份字段或私人文件路径。
