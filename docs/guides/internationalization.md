# 国际化和本地格式

## 文本和布局

界面文字保留在应用的语言层，不写入颜色 Token。中文标签短不代表英文标签也短：以扩展 40% 的文案检查工具栏、按钮和标签页。用户节点名称可以含 emoji 和多种文字，应保留原始 Unicode。

## 数据

时间使用用户时区和本地格式；文件名、服务器地址和协议名称保持原文。排序不要依赖英文小写转换作为所有语言的通用排序规则。数字使用 Intl.NumberFormat 时明确是否需要单位和最大精度。

## 凭据和解析

Base64 内容需要按 UTF-8 解码，不能假设 ASCII。分享链接的 percent encoding 正确还原，错误输入不能触发整个界面崩溃。URL token、密码、UUID 不执行自动翻译或大小写修改。

## 方向和输入法

新建 Web 组件尽量使用逻辑属性 inline/block；代码和 URL 区域保持适当的 LTR 表达。中文输入法 composition 期间不把 Enter 当作提交，待输入完成后再响应键盘提交。

## 第三方界面的显示层翻译

第三方桌面壳或嵌入式 Web 界面没有可用的 i18n 接口时，可以把 DOM 显示层翻译作为受限兼容方案，但不应把它当成产品自身国际化的替代品。只对已知界面节点和 `placeholder`、`title`、`aria-label` 等属性做整段精确匹配；明确跳过输入框、聊天消息、代码块、日志、文件名和用户生成标题，避免翻译或改写用户内容。动态界面可用 `MutationObserver` 处理后续渲染，同时需要控制观察范围并保证重复执行幂等。

实施前保留可恢复的原始资源，并把翻译词典与注入逻辑分离，便于升级后重新应用或单独修正词条。验收不能停在“进程已启动”和“注入标记存在”：还要确认主窗口可见、本地界面请求完成、核心导航可操作，并在失败时立即恢复原资源。曾有 Electron 桌面壳在解包注入后仍能启动进程和本地服务，但主界面请求超时；因此进程级检查只能证明启动链的一部分。

本方案只在界面显示层验证有效；模型生成内容、服务端文案、图片内文字以及新版中未命中的字符串仍可能保持原文。桌面壳、界面服务和远程鉴权同时参与启动时，应分别记录本地注入兼容性与网络可达性，不能把所有白屏都归因于翻译。若产品提供正式语言资源，应优先迁移到官方机制。
