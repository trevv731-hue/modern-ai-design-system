# 动效和性能

## 系统动效表

| 场景 | 参数 | 目的 |
|---|---|---|
| 按钮 | 色变 120–160ms；按压 scale(.98) 100ms | 确认操作可触发 |
| 可点击卡片 | translateY(-1px) 200ms | 表达可导航；静态卡片不使用 |
| 页面进入 | opacity 180ms | 保留上下文，不做大幅飞入 |
| 对话框 | translateY(6px)+scale(.98)+opacity 200ms | 集中注意力 |
| 开关 | 滑块 translateX(18px) 200ms | 表达二元状态 |
| 加载 | 小范围 spinner | 表示任务进行中，不能伪装进度 |

这些是产品约定，并不是声称所有动画都采用某一平台的原生物理算法。当前 Web 卡片采用有界缓动；原有 SwiftUI/Compose 弹簧参考保留。

## 空间与效果

位移和缩放属于空间反馈；颜色与透明度属于效果反馈。颜色不做带 overshoot 的弹簧。避免 transition:all；明确列出 transform、opacity 或必要颜色属性。

## 渲染预算

优先在 transform/opacity 上运动，避免动画修改 top/left/width/height/margin/padding。阴影通常带来绘制开销，不能声称它必然由合成器处理。大区域持续模糊和多层滤镜需要实际性能分析。

一屏可见 blur 区域最多 2 个，是该系统为普通桌面硬件设置的预算。静态检查只能检查规则，不知道多少类被同时使用；浏览器测试检查实际可见节点的 computed backdrop-filter。

## 中断和重复操作

用户快速重复切换时状态保持正确。CSS transition 可以从当前值反向过渡，网络任务则需要取消或串行协调。不得让过场动画阻止取消按钮和错误处理。

## 减少动效

减少动效时停止位移、缩放与连续旋转，保留文字“正在加载”。不把动效当作唯一加载信号。移除原来的 bounce Toast 和连接环持续呼吸动画，避免干扰长时间工作。

## 测试与声明

运行 `npm run lint:motion` 检查明确违例，并在实际页面检查 blur 数量。60fps 是体验目标，需要对应硬件分析才能宣称实测达标；本系统不因静态检查通过而声称所有设备都达到 60fps。

## 桌面产品动效细化

参考 [Microsoft Fluent 2 Motion](https://fluent2.microsoft.design/motion)：顶层导航采用短淡入，避免用大面积滑动暗示页面层级。AetherLink 使用 180ms opacity 动画，切换页面时取消旧动画；控件状态仍立即更新，不等待动画结束。

悬停位移控制在 1px；按钮按压缩小到 .98，连接按钮为 .96。连接状态用静态外环和文字表达，不使用循环呼吸。列表超过 20 条时不逐条延迟进场。减少动效模式下禁用这些动画，保留加载文字和状态播报。

动画参数属于产品约定；不能据此宣称实现了 Apple 原生弹簧或已测得所有设备 60fps。
