# 实时监控工作区

[返回手册](../README.md) · 已在 SSH Desk Electron 桌面工程集成

## 页面层级

连接选择与采样状态置顶；CPU、内存、磁盘、网络是概况；每张 GPU 独立卡片展示利用率、显存、温度、功耗和使用账号；进程表补充 PID、进程名、运行时间和图形／计算类型。低频查看的 UUID、驱动、PCIe、时钟等放在折叠详情中。

内容卡片保持实底。GPU 卡片用于读数，不做悬停漂浮；可导航的服务器卡片可采用 1px 位移反馈。

## 数据语义

- 缺失、N/A、权限不足与已确认零值分开处理，未知不是空闲。
- 利用率采样、显存分配与进程列表回答不同问题，不能互相代替。
- CPU／网络通过两次计数器差值计算；处理计数器重置、时间间隔过长和网卡切换。
- 用户名代表操作系统账号，同一账号的多位使用者无法进一步区分。
- “驱动支持 CUDA”不等于已安装 CUDA Toolkit。不要从某一版本字段推导环境已就绪。
- 短趋势只反映已采样数据；不要填充随机历史或把暂停间隔画成连续测量。

## 采样生命周期

请求串行，每次完成后才安排下一次采样。页面离开、窗口隐藏、暂停后停止定时请求。服务器切换生成新的请求序号；旧回复不能覆盖当前页面。出错保留上次结果，显示更新时间和错误，并提供重试。不得用整页 aria-live 每三秒反复播报所有读数。

统计更新保留滚动位置、展开面板、筛选条件和控件焦点。监控任务只查询，不隐式启动训练、安装软件或终止进程。

## 动效接入

构建后复制 [motion.css](../../web/motion.css) 和 [motion.js](../../web/motion.js)，在产品样式后加载 CSS。它们不强制主题和配色。

```html
<link rel="stylesheet" href="design-system/motion.css">
<script src="design-system/motion.js"></script>
```

```js
const motion = DSMotion.create();
// 只在实际导航时调用，采样刷新不重新播放整页动画。
motion.enter(currentSection);
// 只在读数已确认改变时淡入新值，不虚构中间读数。
motion.update(changedValueElement);
```

使用 ds-motion-button、ds-motion-hover、ds-motion-dialog 提供按压、可导航卡片、原生对话框反馈。空间和透明度分离；快速操作取消旧动画；减少动效立即生效。效果层不包含循环呼吸，也不承诺未经硬件测量的 60fps。

## 标识资源

应用标识优先保留 SVG 原件，再导出 PNG 和包含 16／32／48／64／128／256px 的 Windows ICO。小尺寸确认轮廓和对比度；业务图标沿用统一笔画。品牌标识可以有独立配色，不把品牌色写入通用组件。

## 验收

- 两张卡及不同账号进程能对应正确，图形服务不会误报为训练任务。
- 首次采样不会伪造 CPU／网络速率；断线不会显示“没有任务”。
- 连续切换、暂停／继续、隐藏窗口与返回页面不会积累定时器或覆盖状态。
- 键盘可操作全部控件；原生弹窗保留焦点行为。
- 减少动效下无位移、缩放或连续旋转；实时读数不闪烁。
- 真实环境与演示截图区分，演示值不流入正式状态。

## AI 用量与费用监控

问题：本地会话日志可能反复输出同一累积计数；同一流式消息可能有多个内容块。直接逐行累加会放大用量。另一个常见误导是将 API 单价折算金额当成订阅扣费，或者将未接入数据源的应用显示为零消耗。

决策与适用条件：

- 累积计数按差值记录，重复检查点不新增用量；计数器重置时需要独立处理。消息级日志按会话与消息标识合并重复快照。日志条目数应标为“用量记录”，未经 HTTP 证据不能称为精确请求数。
- 分开记录应用、供应商、原始模型名。应用使用第三方模型时，不能根据应用名称套用原厂模型价格；当前配置也不能证明历史日志的供应商。模型别名和缓存计费字段需要验证。
- “实际账单”“按单价估算”“手动记录的订阅月费”分别展示。未配置单价显示未知，部分定价必须显示覆盖条数；缓存读取和写入不能无条件采用同一单价。
- 检测到应用目录，只能证明存在本地数据目录，不能证明已接入 Token 或账单。数据源卡片应显示已采集、等待有效记录、读取失败、暂不可获取等状态。
- 额度窗口显示最近快照时间，过了重置时间标记过期，不能将旧百分比作为实时剩余额度。
- 固定时间范围的热力图若不跟随明细日期筛选，要在图旁明确说明。无日志格表示无记录，不能推断当天完全没有使用。
- 隐藏窗口停止周期刷新，但首次读取仍可完成，避免后台启动后一直停留在“准备读取”。保留筛选、搜索和分页状态，逐次刷新不覆盖用户正在编辑的定价表单。

验证：在本地 Electron 用量监控迭代中，9 项自动测试覆盖累积计数重复与重置、流式消息合并、未知定价、设置校验、时区、文件追加／删除／未完整行及重定向配置目录的保存兼容性；打包后的桌面窗口验证真实日志渲染、应用筛选、设置弹窗、设置保存／重读与无整页横向溢出。

未验证边界：不同版本第三方接口的缓存字段、其他设备的日志、真实账单对账，以及未接入的封闭客户端用量。以上统计语义属于通用原则；具体应用列表、配色和刷新间隔属于单产品选择，不作为设计系统默认值。
