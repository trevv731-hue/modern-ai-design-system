# 场景：设置和权限

## 分组

按照用户任务分为网络、系统集成、外观和关于，不按照源代码模块命名。设置标题解释作用，帮助文字说明什么时候生效。危险设置要说明影响。

## 立即生效与保存生效

主题和密度可以立即生效。需要重启连接的端口在连接期间禁用，帮助文字说明断开后可修改。多字段事务使用显式保存按钮；不要让一个表单混合两种生效方式却没有说明。

## 验证

端口必须整数 1–65535，控制器和代理端口不同；错误出现在字段附近，输入值保留。开关依赖后端确认时显示 pending，失败回到原状态。

## 未实现功能

开机自启动、TUN 或静默启动未实现时禁用，旁边显示“尚未支持”。不能只改变 checkbox 并提示“已开启”。如果只是概念预览，整块区域明确标明未生效。

## 权限

请求权限前说明真实功能和必要性，拒绝后提供替代路径。不要在阅读设置或打开页面时自动执行外部修改。

## 私人数据的设备授权与恢复

问题：仅提供软件令牌入口会使浏览器无法直接查看；只加设备凭证又可能在换机后锁住本人。适用于单人私人数据工作区的决策是：日常设备授权、独立备用恢复、管理端重置分开设计。恢复入口应在未授权状态可找到；管理权限是重新签发凭证的依据，不代表浏览器能自动识别网站拥有者。设备凭证过期、恢复会话到期、撤销与换机各自说明下一步。共享电脑上的免提示访问必须明确其 Windows 用户/浏览器使用边界。

公开快捷入口与访问权限是两件事：公开链接可暴露地址，但不能绕过后端授权。页面只保留必要名称、操作与状态，重复的“独立空间”“私人专属”和操作说明移出常驻界面；覆盖、删除、本机副本丢失等决策所需提示仍保留。浏览器自动选择客户端证书属于客户端策略，网页不能自行关闭系统证书选择；策略只匹配必要域名与证书，写入失败时交付可审阅配置，并明确尚未生效。

软件同步凭证与站长凭证分开；旧客户端新增认证时，同时提供配对与失败提示。本机保存、等待上传、服务端确认三种状态不能混写。密钥不放在网址、静态资源、公开源码或维护文档中，维护代理不保留独立后门。保护需覆盖页面、数据接口及备用域名；私人数据渲染仍需防止脚本注入。

验证记录（2026-10-16）：已验证本机证书和恢复会话可读取、匿名和其他来源的请求被拒绝、证书撤销/错误指纹和会话篡改/过期测试、应用令牌隔离、配对验证失败不保存、旧客户端未配对保留本机数据。设备证书优先是本次单产品选择，不作为所有产品的默认登录方式。未验证边界：浏览器完全无提示、其他浏览器/操作系统的证书选择，以及真实丢机后的完整管理端恢复演练；系统策略写入失败时不能显示“自动进入已配置”。本次专题构建通过，设计系统完整测试在既有组件数量校验处失败（实际 81、预期 75），未改写该计数来掩盖问题。

## 关于

显示真实版本和已验证能力。内核版本从 API 获取，无法获取时显示未知；不填固定的旧版本和随机内存数据。帮助链接和退出托盘说明应可找到。

## 公开产品与私人后台的边界

问题：公开页面中的后台链接、同步地址、错误详情和旧配置文件会暴露私人服务信息；移除入口仍不能替代接口鉴权。通用决策：浏览器仅访问同域业务接口，跨服务通信走内部绑定，服务凭证仅保存在服务端；转发使用固定路由白名单，重建请求头，剥离上游地址、重定向与实现细节。授权先于数据库访问；来源校验和 CORS 不能单独作为身份凭证。隐去私人管理入口是本次单产品偏好，不推广为所有产品默认隐藏登录。

验证（2026-10-16）：匿名访问各数据操作均被拒绝；内部令牌在公开域名无效；网关不转发浏览器 Cookie，且拒绝上游重定向；前端构建扫描无私人服务域名与旧存储配置。应用层快照加密已验证随机密文、正确密钥往返及错误密钥拒绝。未验证边界：历史 DNS、证书透明度、外部搜索缓存和旧发布版本不能靠本次前端改动消除，不承诺私人地址不可推断；服务端解密不等于端到端加密。

本轮文档回流构建通过；组件计数断言（实际 267、预期 261）已定位并修复：差异来自 6 个已在 react.tsx 与 components.css 中实现、但漏登记进 catalog 的组件（SLA 升级倒计时器、隔空播放路由面板、磁头消磁脉冲表、空间锚点变换控件、Actions 步骤耗时汇总、Figma 样式变量迁移卡）。已补齐 catalog 条目而非改断言迁就数字，组件数 278→284、React 组件 261→267，全量验证恢复通过。线上授权读取与匿名拒绝均验证；已有快照密文解密验证通过。并发发布曾撤掉授权和加入无密钥明文回退，已恢复并新增独立回归测试与工程安全约束；发布前必须检查当前源码，不能只依赖之前测试结果。

快捷入口与文案精简验证（2026-10-16）：公开入口跳转正确，匿名数据请求仍被拒绝；主站及私人首页手机布局无溢出、无脚本错误，19 项服务端测试通过。自动选证书配置仅完成文件格式与范围校验；Windows 策略写入被拒绝，管理员导入与浏览器实际自动选择未验证。

## 恢复入口与备份结果的真实性

问题：边缘限速可能因网络出口和节点分散而低于预期；“保存成功”也可能掩盖历史备份失败。决策：安全依赖独立密钥、服务端授权和失败时拒绝，而不依赖代码难读。分布式限制先验证计数范围；本次单站长产品对恢复入口增加共享数据库原子计数，并保留证书入口。全局限制会牺牲攻击期间恢复入口的可用性，不适合直接用在多用户共享登录。

备份头、元数据和历史在同一事务中提交；解密、历史写入或确认数据异常时不能提示成功。用户指定恢复设备不存在时明确报告，不替换成别人的/另一设备的档案。严格 CSP 下的交互通过事件绑定实现，不能把设备名拼接进事件脚本，或为修复按钮而允许任意内联脚本。

验证（2026-10-16）：事务中历史写入失败时旧版本和元数据保留；错误密钥解密不被当作空记录；跨设备标识确认错误不标记同步成功；恶意名称和引号标识的浏览器交互回归通过。线上两个入口均验证过量恢复尝试返回 429，证书授权仍可访问。原按 IP 的试验未达到跨出口限制要求，已改成全站点共享计数。未验证边界为独立渗透测试、大规模分布式压力和真实丢机恢复；浏览器自动选证书仍等待用户手动配置。
