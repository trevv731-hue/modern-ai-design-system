# 个人桌面记录工具

来源：2026-10-15 LeetCode 桌面工具设计迭代。此页记录可复用经验，不把单个产品偏好强加给所有产品。

## 内容优先

窗口使用产品名；个人单账号工具默认显示“已登录”，用户名放到确实需要区分账号的设置中。避免同时出现个人品牌、英文副标题、工作台面包屑和鼓励语。主标题写任务名称，主按钮写操作。

单一页面默认展示日期、三项核心指标、历史活动和当天明细。侧栏只放真实页面入口；若入口不足两个，优先评估移除侧栏。主界面无需重复解释采集架构。

## 柔和配色

参考暖纸张和低饱和陶土色，不复制外部产品品牌。可选样式 `web/warm-paper.css` 覆盖语义变量，需在默认主题后载入。单主题产品不展示没有需求的主题切换。强调色集中用于主操作、焦点和选中态；常规统计使用正文色。

柔和不等于低对比度。普通文本仍以 4.5:1 为验收目标，小字和禁用状态不能用同一颜色；热力图不能只靠颜色表达数量，应附日期与数量文本（键盘可访问提示或等价明细）。

## 采集与同步状态

- 未登录、尚未采集时使用未知值或明确说明范围，不能把缺少数据解释成真实的零。
- 有采集结果且当天无记录才显示零；首次导入有限制时必须说明覆盖范围。
- 区分“已获取到本地”和“已上传到网站”，分别显示时间，上传失败不清空本地数据。
- 时间统计明确时区；题数按题目去重，提交数按提交记录计数。
- 关闭到托盘与退出不同，保留明确退出操作。

## 经验回流

每次实际产品迭代后，将可复用模式、踩坑、验证范围记录到对应专题；只有重复出现或有实际需求时才提取组件。区分“实现并验证”“方案待验证”“单产品偏好”。不要把一次视觉选择变成全局强制规则，不在设计系统加入账号、密钥或真实提交记录。

本次已验证 Windows Electron 启动、设置保存、365 日网格和暖色样式；真实力扣登录采集、网站线上同步及完整无障碍验收尚待验证。

## 历史记录迭代补充

后续已验证中国站真实账号的历史分页、题目目录匹配和接口末页。经验：列表接口可能不提供题目链接，需要从当前题目目录补齐元数据，不能把缺失链接当成整批记录无效；详情接口逐条调用易触发限流，优先缓存目录并复用。分页导入每页保存，遇到访问限制等待后重试；“完整”以接口末页为依据，不能把批量上限写成完整历史。

复习场景默认展示去重题目，保留累计提交数与是否曾通过，并提供所有提交和日期视图、题号及题名搜索。一次通过后再次失败不能抹掉“曾通过”状态。该经验不包含用户实际题目或提交数据；网站同步与完整无障碍验收仍待验证。

## 分页、日历与后台同步补充

长记录采用固定页容量与页码；搜索、页容量或筛选变化时回到第一页，总页数变化时钳制当前页，禁用无法执行的上一页和下一页。默认采用较小的页容量，避免“显示更多”无限扩展内容高度。

热力图的颜色只映射一个明确指标；Accepted 提交次数不等同于去重通过题数。月份与星期提供定位，指针悬停和键盘聚焦显示日期与精确数量，点击某日进入当天记录。浅色与深色不能承担解释指标口径的责任。

登录收进紧凑账号入口；主页只保留实际指标与简短同步状态。后台同步使用状态灯和失败详情，不在每次成功后显示“操作完成”。“已同步”必须以服务端实际写入成功为前提。不同软件的数据空间与凭证独立，自动上传不能代替首次设备授权。

## 动效参考补充

参考用户提供的云顶战绩界面，只吸收按压与弹层的节奏，不复制视觉装饰。按钮按压约 110 ms，分页淡入与 6px 位移约 180 ms，弹层入场约 240 ms、离场约 130 ms。只变换 opacity/transform，快速操作取消前一动画，后台轮询仅在数据变化时更新列表，不重播同一状态。减少动效模式关闭这些动画，保留所有功能。

验证范围：Electron 分页容量、搜索后页码、日期数量提示、键盘可达提示、减少动效、真实云端写入与独立临时库恢复。并发编辑采用冲突保留，不宣称自动合并；未来设备的统一账号登录仍需单独实现。参考应用的目录数据库可能是旧副本，必须追踪快捷方式、入口脚本和实际运行数据路径后才迁移数据；统计时区分所有档案总数和当前账号/赛季数。

当前配对设备的自动同步与私有云端查看已通过实际打包版验证。同步状态必须区分“已配对”“同步中”“已同步”“待重试”；历史上曾同步成功并不代表现在连接健康。服务域名迁移可能遇到旧解析缓存，接口应固定可信来源并保留 TLS 校验，不能通过随意转发鉴权头或关闭证书检查掩盖连接失败。

## 独立试用与安静保存

公开工具与私人档案可采用不同权限：工具页面供访客使用，私人保存/导出由后端校验。未授权的正常访客进入本机记录模式，不强制跳转站长授权页，也不把 401 当网络故障无限重试。没有公开入口不能代替接口鉴权。后台管理站点可绑定同一数据空间，避免为接入控制台复制档案；访客记录不能自动进入站长档案。本轮已验证匿名页面返回成功、私人 API 拒绝、站长可读，以及两个站点读到同一份档案；跨浏览器和跨设备访客持久化仍受各自本机存储约束。

问题：直接在旧站试做新界面，会把试用与数据迁移混为一件事。新版试用宜使用独立来源、源码分支和数据空间；是否迁移是另一个决定，不能读取旧浏览器记录并默认上传。参考 App 的静态拆解只能支持已观察到的页面结构和字段，不能据此宣称像素级或完整功能还原。

本次私人健身试用选择“训练、动作、历史、我的”四入口，主页面只放日常任务，后台保存不展示基础设施面板。这是单产品偏好，不替代其他产品必要的失败反馈。安静保存仍需鉴权、版本条件写入、失败保留与自动重试；进行中的训练在原设备恢复。媒体未包含在记录接口中时，在备份页面说明当前设备存储的边界。

复用主题时，保留真正生效的外观控制；若主题覆盖了强调色，就移除无效的颜色选择。手机日历、底栏和模板列表需实际检查 390px 溢出和任务流程，不只看桌面截图。验证记录（2026-10-16）：独立接口鉴权和冲突测试、后台保存/失败重试测试、模板创建到完成训练及历史查看的浏览器流程、浅色/深色切换、手机与桌面布局已验证。iPhone 真机、长期离线、多设备真实并发和像素级一致性未验证。

回流验证：专题构建通过，动效校验与动效测试通过；设计系统完整验证在现有组件导出数量断言处失败（当时实际 105、预期 99），没有为本次文档回流改动组件源码或放宽断言。


## 安装包素材引用与可浏览交付

问题：大小写敏感的资源包在 Windows 落盘时，可能覆盖仅大小写不同的文件；提取目录的数量与可打开状态不足以证明素材完整。适用于 APK、ZIP 等跨文件系统资源迁移。决策：先检查归档条目的大小写冲突，按精确归档路径读取，以唯一编号或路径编码落盘，保留原路径与哈希对照；目录展示可识别动作名并提供搜索，不让用户逐个猜混淆文件名。

资源清单分清实际本地文件、包内文本、远程引用与依赖授权的内容。低分辨率动画不标为高清视频；界面写有“会员专享”不能证明正文或视频已随包打入。静态表达式未求值时保留证据，不用猜测值填补数据。

验证（2026-10-16）：一次 APK 资源恢复检查了归档路径冲突，直接读取原条目，对所有新输出逐项校验哈希并检查图片解码，建立中文动作和素材关联。未验证目标 App 运行页面、远程内容、会员可见范围或完整动画播放。本次为通用导入与交付原则，未修改组件或 Token 源码；不包含账号、密钥及私人业务数据。


## 会员预览与内容分发边界

问题：只在客户端截取前三条、加遮罩或隐藏按钮，不能保护已随安装包完整分发的文字与数据。适用于付费教程、会员动作讲解与素材预览。决策：明确公开预览、受保护正文与授权后离线缓存的边界；需要保密的正文由服务端鉴权返回。拥有终端的用户仍可能读取授权缓存，不把客户端加密宣称为绝对保护。

验证：一次安装包静态核查同时观察到本地完整讲解数据、预览组件截断前三条及付费提示，未请求业务接口。此为分发边界证据，不代表已验证线上会员归属、服务端漏洞或视频签名失效。公开页面返回 HTTP 200 时仍须核验正文结构，验证码页面不能记作下载成功。本次只更新专题文档，无组件或 Token 源码变更。


本地资料交付补充：用户要“直接看内容”时，优先提供可打开的浏览入口与可携带的原文件包，而非仅给资源清单。大素材集合按固定容量分页、延迟加载；详情保留原图尺寸，搜索覆盖中文名称、别名和分类。需支持直接打开的 HTML 宜内嵌索引并用相对路径引用素材，避免依赖 file 协议下受限制的 fetch；打包保留同一相对目录，界面不把远程引用呈现为可播放文件。

验证：一次离线内容库通过本机回环 HTTP 的浏览器检查，涵盖中文搜索、完整十条动作讲解、课程多图、空状态、分页、Escape 关闭与焦点恢复，以及 390px 无横向溢出；全部引用文件存在，压缩包另做 CRC 校验。浏览器工具拒绝 file 协议，因此没有把回环 HTTP 验证称为双击模式实测；跨浏览器与移动真机尚未验证。本次只更新专题文档，无组件源码改动。
## 显式计量与记录复用

问题：数量、显示单位与营养标示基准是不同维度，混在一个数字中会导致编辑或复用时重复换算。适用于食物份量、包装规格和其他按数量折算的个人记录。

决策：分别存储实际数量、计量单位、每份规格和统一计算基准；用户明确填写每份克数后才允许克／份换算，缺失值与明确的零分开。展示时舍入，内部换算保留精度；编辑沿用原记录 ID，删除保留可合并的删除标记。历史复用使用已验证的记录，不凭名称编造默认数值。

验证（2026-10-16）：手机端记录工具已测试 1.5 份 × 200g、每份160大卡得到240大卡，修改为1份后为160大卡且没有新增重复记录；验证换日隔离、刷新保留、删除与离线档案合并。259项相关回归通过，390px浏览器无横向溢出。未验证多台真实设备并发、移动真机和完整营养数据库；蓝色强调及卡片布局属于该产品偏好，不是共享主题要求。本次仅补充现有专题，无组件或Token源码改动。

工程交付隔离补充（2026-10-16）：可运行工程和抓包／逆向输入分别存放；交付目录只带运行所需源码与素材，原始安装包和分析工具保留在外部参考目录。独立文件夹还需验证Git元数据与依赖不是其他项目的worktree或junction。一次手机端记录工程分离已逐文件核对3,113个源码／素材文件哈希、独立安装依赖并构建通过；未因此声称线上部署已更新。此为工程交付原则，不改变共享视觉或组件源码。

## 逆向控件语义推断与布局上下文判别（2026-10-16）

- **同名控件须连同布局上下文与输入属性判别**：
  在从逆向布局（XML/NIB）反推业务模型时，相同的控件 ID 可能在不同场景承担完全相反的语义。例如 `etUnit` 在修改食物弹窗中配置了纯数字 `inputType="0x2"`（表示重量数值输入），而在纠错弹窗中则是带 `maxLength="200"` 的多行文本框（表示自由语言纠错）；带 `et` 前缀的 `etCal` 实际类型是只读 TextView 而非 EditText。不能仅凭 ID 命名臆断控件类型与可编辑性。
- **界面静态文案不代表运行时校验或真实配额**：
  布局中的“/100”字数指示在 XML 中可能并未声明 `maxLength` 约束；设计稿占位文案（如“会员试用｜剩余次数：2”、“今日使用已达上限”）仅是默认文本，真实业务逻辑、额度鉴权与降级策略完全由服务端接口在运行时驱动，不能仅凭静态文案断言客户端具备本地限额逻辑。
- **无离线数据不等于只能纯云端识别**：
  安装包内未打包离线食物营养字典（如本地仅有闹钟与运动分组 SQLite），表明食物与热量换算完全依赖在线 API；对于识别算法（端侧推理 vs 服务端推理），在加固壳未脱、未捕获网络请求前，应保持客观边界，不凭空断言引擎位置。
