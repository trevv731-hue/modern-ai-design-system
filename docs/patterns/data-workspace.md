# 场景：列表、搜索和筛选

## 结构

页面标题与真实总数 → 搜索/筛选工具栏 → 列表或网格 → 空状态/分页。只有任务确实需要比较多属性时才使用表格，少量节点可用信息卡。

## 搜索

搜索名称、地区和服务器等非凭据字段。提供清楚的搜索名称；Ctrl/Command+K 只有实际绑定后才展示提示。大数据可以防抖；小型本地列表立即过滤即可。

## 筛选

协议等互斥选项可用分段按钮组；多选条件用 checkbox；大量选项使用 select。筛选不改变底层数据。无结果时保留筛选条件并提供清除，而不是表示用户没有任何节点。

## 行内动作

选择节点和删除节点保持不同的按钮语义。不要把可点击 div 作为唯一选择入口。删除按钮不能通过事件冒泡同时选择节点。敏感地址展示需要控制截断并允许有意识的复制。

## 批量任务

并发测速限制并发数量，逐条更新真实结果；未知先显示未测速。失败节点标为超时，不生成随机延迟。任务完成消息说明结果而不是笼统宣称全部成功。

## 扩展

当列表多到影响渲染时再引入虚拟化；测试活动项在滚动与过滤后仍可访问。不要在第一次设计时强行引入分页、分组、无限滚动和复杂拖拽的全部组合。
